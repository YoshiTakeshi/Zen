Money tied to metal, proved in 196 bytes.

Zen is an open-source monetary system: three physical coins of gold, silver and copper, and three electronic coins on three public chains. The metal coins are the reference. Every block of payments is checked by one small proof.

Six coins, one reference

Each physical coin is a small piece of metal anyone can weigh. Each electronic coin lives on its own chain. The aim is one electronic coin for one physical coin, with no custodian and no price feed in between.

The designs and files for the physical coins are in the physical coins folder of the repository. Each block is proved correct by a single proof of 196 bytes, so a node that checks only the proof reaches the same answer as one that replays every payment. Amounts are counted in base twelve, which divides evenly by 2, 3, 4 and 6.

Where the work stands

Built and tested

  • A Rust node, wallet and three-chain test network that run on one laptop, with a wallet page in the browser.
  • Payments, payment channels, channel factories, vaults, orders and auctions.
  • One 196-byte proof per block that covers payments and every one of these operations. A node checks it in a few milliseconds.
  • 583 rule-breaking tests that try to make the proof circuits accept something the node refuses. None succeeds, and a deliberately removed rule was caught.
  • 137 automated tests pass. The code was written with AI assistance and is tested in the open.

Needed next

  • A public multi-party ceremony to create the proof key. Today's key was made on one machine and is for testing only.
  • An independent audit of the circuits and the consensus rules.
  • Fuzzing of every message decoder.
  • A public test network that others can join.
  • Speed tests of the proof builder on GPU servers, and of the wallet on phones.
This is a test network. The test coins have no value, the code is not audited, and nothing here is an offer of any financial product.

Help build it

Zen is built in the open and needs people who will look for what is wrong with it. An hour of careful review is worth more than praise.

Cryptographers

Read the proof circuits and the soundness tests, and try to break them. The proofs use Plonky2 and Groth16.

Rust developers

Review the node, the transport and the wallet, write fuzzers, and fix what they find.

Ceremony participants

Take part in the public setup of the proof key. Each participant adds randomness, and one honest participant is enough.

Testers

Run the test network on a Mac or Linux machine, and later on a phone, and report what fails.
